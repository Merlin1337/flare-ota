First public release of **flare-ota**: self-hosted OTA updates for Expo, 100% on Cloudflare, for the standard `expo-updates` client.

```sh
npm i -D flare-ota
```

### Server (Cloudflare Worker, D1, R2, Access)
- Expo Updates protocol v1 with mandatory code signing and fingerprint runtime versions
- Channels and branches, progressive rollouts (they only grow), pause, rollback to the previous bundle or to the embedded JS, promote between branches
- Signed, expiring, revocable preview links (QR) that pin one device to a release, using `setUpdateRequestHeadersOverride` (anti-bricking protections stay on)
- Adoption metrics per release and platform; failed launches are recorded and never re-offered
- Dashboard behind Cloudflare Access, with the Access JWT verified by the Worker; first-run checklist, confirmation before rollbacks, audit log
- Remote MCP server (Streamable HTTP) with scoped tokens
- Content-addressed assets verified by SHA-256 on upload, edge-cached, daily garbage collection
- Guided, rerunnable setup with Cloudflare's new `cf` CLI: signing key, Access, D1, R2, deploy, first token, WAF rules

### CLI (`flare-ota` on npm)
`init`, `doctor` (checks the server's signature against your app's certificate), `publish`, `rollout`, `pause`, `resume`, `rollback`, `promote`, `preview` (QR in the terminal), `metrics`, `channels`, `tokens`, `audit`, `mcp` (stdio). `--json` everywhere. Plus `flare-ota/expo` for preview links in the app.

### Validated
End to end on an iOS release build (Expo SDK 58) against a real deployment: signed publish → update, rollback to previous, rollback to embedded, preview pinning. Not yet exercised on a device: Android and `exitPreview()`.
