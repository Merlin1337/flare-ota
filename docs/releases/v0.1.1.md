A friendlier `flare-ota publish`.

```sh
npm i -D flare-ota@0.1.1
```

- **Checks before building anything**: app config and `updates.url`, token scope, which channel serves the branch, and that the server's signing key matches the certificate in your app (codeSigning usage included). A mismatch stops the publish before the export. `--skip-checks` skips the signing checks.
- **Live progress**: a spinner per step with its duration, bundle sizes per platform, an upload progress bar, and how many files the server already had. Plain lines in CI, nothing extra with `--json`, `NO_COLOR` respected.
- **A closing summary**: devices seen on each runtime, the rollout, a link to the release in the dashboard, and the next commands (preview, raise the rollout, roll back).
- **Warns when no channel serves the branch**, since no device would get the update.
- The MCP `publish_update` tool returns the same step log, so agents see what was checked.
- Server: `/api/v1/whoami` also returns `dashboardUrl` when `DASHBOARD_HOST` is set. Older servers still work; the summary just has no dashboard link.
